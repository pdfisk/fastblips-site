Crumb UI Widgets
================

This document describes the widget classes used to build the Crumb user
interface. All widgets derive from a common Widget base, and are arranged in
a tree whose root is the single Viewport.


Class hierarchy
---------------

  Widget (abstract)
    Panel (abstract)
      Viewport (singleton)
      HPanel
        Navbar (singleton)
        ButtonBar
      VPanel
      SplitPanel (abstract)
        HSplitPanel
        VSplitPanel
      Window
        HSplitWindow
          ConsoleWindow
        TranscriptWindow (singleton)
      TextPanel
      ListPanel
    Menu
    Button
    Spacer


Widget (abstract)
-----------------
The abstract base class of every UI element. Widget is never instantiated
directly; only its concrete subclasses are.

  - Owns a DOM element and knows its parent widget (null for the Viewport).
  - Has a position and size, set by its parent during layout.
  - Can be shown or hidden; a hidden widget takes no space.
  - Provides layout() to size and position itself, and dispose() to remove
    itself and release any event listeners.


Viewport (singleton)
--------------------
The outermost container. It fills the whole browser window and is the root
of the widget tree.

  - Exactly one instance exists; obtain it with Viewport.instance. Calling
    the constructor a second time is an error.
  - Holds an optional Navbar docked at the top, and one content widget that
    fills the space below it.
  - Hosts Windows, which float above the content area. The Viewport keeps
    their stacking order and brings a window to the front when it is
    clicked.
  - Listens for browser resize events and lays out the whole tree again.
  - windows returns the open Windows, back to front.


Panel (abstract)
----------------
A widget that contains other widgets. Panel is never instantiated directly;
subclasses decide how the children are arranged.

  - add(child), remove(child), and a read-only children list.
  - Adding a child sets the child's parent; a widget can belong to only one
    panel at a time.
  - Subclasses implement layout() to place their children, then ask each
    child to lay itself out.
  - Optional padding around the children and spacing between them.


HPanel and VPanel
-----------------
Panels that arrange their children in a single row or column.

  - HPanel places children left to right; VPanel places them top to bottom.
  - Each child has either a fixed size or a flex weight along the main axis.
    Fixed-size children are placed first, and the remaining space is shared
    among flex children in proportion to their weights.
  - On the cross axis, children stretch to fill the panel by default.
  - Nesting HPanels and VPanels builds grid-like layouts.


HSplitPanel and VSplitPanel
---------------------------
Panels with exactly two children separated by a divider the user can drag.
Both share an abstract SplitPanel base.

  - HSplitPanel places its children side by side with a vertical divider;
    VSplitPanel stacks them with a horizontal divider.
  - The divider position is stored as a fraction (0.0 to 1.0) so the split
    keeps its proportions when the panel is resized.
  - Each side can have a minimum size; the divider cannot be dragged past
    it.
  - Fires a change event when the divider moves, so the position can be
    saved and restored.
  - Double-clicking the divider may reset it to its default position.


Window
------
A top-level panel that floats above the Viewport's content.

  - Has a title bar showing a title and a close button, and a content area
    that holds a single child widget.
  - Moved by dragging the title bar; it is kept within the Viewport so the
    title bar can always be reached.
  - Resized by dragging its edges or corners, down to a minimum size.
  - close() removes the window from the Viewport. A close event is fired
    first, and a handler may cancel it (for example, to confirm unsaved
    changes).
  - Clicking anywhere in a window brings it to the front; isFront tells
    whether it is the front-most window.
  - Has a ButtonBar (window.buttonBar) along its bottom edge, 30px high,
    below the content area. Subclasses add their buttons to it.


TextPanel
---------
A Panel that contains a single text area filling its entire area.

  - The text area is created by the panel and always sized to match it; no
    other children can be added.
  - Exposes the text through a text property (get and set), and fires a
    change event when the user edits it.
  - Can be made read-only, e.g. for program output.


ListPanel
---------
A Panel that is filled by a single List element.

  - The List is created by the panel and always sized to match it; no other
    children can be added.
  - Items are added, removed or replaced through the panel, and the List
    scrolls when they do not fit.
  - Tracks the selected item and fires a select event when the user picks
    one (by click or keyboard).


Navbar (singleton)
------------------
The navigation strip docked along the top of the Viewport. Navbar is a
subclass of HPanel, so its contents are laid out left to right using the
same fixed-size and flex rules.

  - Exactly one instance exists; obtain it with Navbar.instance. Calling
    the constructor a second time is an error.
  - Added to the Viewport (viewport.navbar = Navbar.instance), which docks
    it at the top of the page.
  - Is 35px high and spans the full width of the Viewport. Windows cannot
    be dragged above it.
  - Its children are a title or logo on the left and the navigation items,
    typically Menus; a flex spacer can push items to the right-hand end.
  - Each item has a label and an action; the active item is highlighted.
  - Items that do not fit may collapse into an overflow menu on narrow
    screens.


Menu
----
A pulldown menu: a labelled button that opens a list of items when clicked.
Menu is a Widget, not a Panel; its items are not widgets.

  - addItem(label, action, { checked }) adds an item. Choosing the item
    closes the menu and runs action().
  - If checked is given, it is a function called each time the menu opens;
    a check mark is shown next to the item while it returns true.
  - Only one menu is open at a time. Clicking outside the menu or pressing
    Escape closes it.
  - The list is drawn above all Windows, and kept inside the browser window.
  - Setting itemsProvider to a function makes the menu dynamic: the function
    is called each time the menu opens and returns the items to show, in the
    same {label, action, checked} shape. "(none)" is shown for an empty list.


Startup
-------
When the program starts, the Navbar is docked at the top of the Viewport
with a Console button followed by a Windows menu, which is always the last
item, and the TranscriptWindow is open.

  - The Console button opens a new ConsoleWindow.
  - The Windows menu lists every open window by title, front-most first,
    with a check mark on the front-most one. Choosing a window shows it (if
    hidden) and brings it to the front.
  - The TranscriptWindow is always listed, so choosing it reopens it after
    it has been closed.


Button
------
A clickable, labelled Widget.

  - new Button(label, action); clicking it runs action().
  - label and enabled properties.
  - Used on the Navbar and in ButtonBars.


ButtonBar
---------
A row of Buttons along the bottom of a Window. ButtonBar is a subclass of
HPanel.

  - Is 30px high and spans the full width of the Window.
  - addButton(label, action) creates a Button, adds it and returns it.
  - Buttons are left-aligned, in the order they were added.


HSplitWindow
------------
A Window whose content is an HSplitPanel.

  - left and right properties get or set the two sides of the split.
  - Accepts the usual Window options plus left, right and position (the
    fraction of the width given to the left side).


ConsoleWindow
-------------
An HSplitWindow for running Crumb code. Any number can be open at once.

  - The left side is an editable TextPanel holding the source; the right
    side is a read-only TextPanel showing the output.
  - Its ButtonBar has, from the left, Run (runs the source), Clear Output
    (empties the output) and Clear Input (empties the source) buttons.
    Ctrl+Enter in the source also runs it.
  - Load and runtime errors are shown in the output, in the section 11
    diagnostic format.
  - Lines written by the Transcript built-in are appended to the
    TranscriptWindow rather than to the console's output.
  - Each new console is titled Console, Console 2, ... and opens slightly
    below and to the right of the previous one.


TranscriptWindow (singleton)
----------------------------
A Window showing the transcript: a log shared by every console.

  - There is only one; TranscriptWindow.instance creates it on first use,
    and constructing a second one throws.
  - Its content is a TextPanel (transcriptWindow.textPanel). Each call to
    the Transcript built-in from a ConsoleWindow appends one line to it and
    scrolls it into view.
  - Open at startup and always listed in the Windows menu (see Startup).
  - Closing it only hides it: the instance and its text are kept, and the
    Windows menu reopens it. dispose() discards the instance, and the next
    use creates a new one.


Spacer
------
An empty Widget with a flex weight (1 by default). Placed in an HPanel, it
takes up the free space, pushing the widgets after it to the right.
