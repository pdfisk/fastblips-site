Crumb UI Widgets
================

This document describes the widget classes used to build the Crumb user
interface. All widgets derive from a common Widget base, and are arranged in
a tree whose root is the single Viewport.

Widget (abstract)
-----------------
The abstract base class of every UI element. Widget is never instantiated
directly; only its concrete subclasses are.

  - Owns a DOM element and knows its parent widget (null for the Viewport).
  - Has a position and size, set by its parent during layout.
  - Can be shown or hidden; a hidden widget takes no space.
  - Provides layout() to size and position itself, and dispose() to remove
    itself and release any event listeners.


Viewport (singleton)
--------------------
The outermost container. It fills the whole browser window and is the root
of the widget tree.

  - Exactly one instance exists; obtain it with Viewport.instance. Calling
    the constructor a second time is an error.
  - Holds an optional Navbar docked at the top, an optional StatusBar docked
    at the bottom, and one content widget that fills the space between.
  - Hosts Windows, which float above the content area. The Viewport keeps
    their stacking order and brings a window to the front when it is
    clicked.
  - content is the widget filling the space between the Navbar and the
    StatusBar (or null); Windows float above it. Any widget with a height
    can be docked as the StatusBar (the ?run= page docks a ButtonBar).
  - Listens for browser resize events and lays out the whole tree again.
  - windows returns the open Windows, back to front.
  - visibleWindows and minimizedWindows return the Windows that are
    showing, and those that are minimized.
  - arrangeWindows() cascades the showing Windows diagonally from the top
    left, each sized to 35% of the Viewport's width and height and offset
    30px from the one behind it, front-most last and on top; minimizeAll(),
    restoreAll() (un-minimize and un-maximize) and closeAll() act on every
    Window. The playground's Windows menu offers all four above its list
    of windows.


Panel (abstract)
----------------
A widget that contains other widgets. Panel is never instantiated directly;
subclasses decide how the children are arranged.

  - add(child), remove(child), and a read-only children list.
  - Adding a child sets the child's parent; a widget can belong to only one
    panel at a time.
  - Subclasses implement layout() to place their children, then ask each
    child to lay itself out.
  - Optional padding around the children and spacing between them.


HPanel and VPanel
-----------------
(src/ui/widgets/hpanel.js, vpanel.js)
Panels that arrange their children in a single row or column.

  - HPanel places children left to right; VPanel places them top to bottom.
  - Each child has either a fixed size or a flex weight along the main axis.
    Fixed-size children are placed first, and the remaining space is shared
    among flex children in proportion to their weights.
  - On the cross axis, children stretch to fill the panel by default.
  - Nesting HPanels and VPanels builds grid-like layouts.


HSplitPanel and VSplitPanel
---------------------------
(src/ui/widgets/hsplit-panel.js, vsplit-panel.js)
Panels with exactly two children separated by a divider the user can drag.
Both share an abstract SplitPanel base.

  - HSplitPanel places its children side by side with a vertical divider;
    VSplitPanel stacks them with a horizontal divider.
  - The divider position is stored as a fraction (0.0 to 1.0) so the split
    keeps its proportions when the panel is resized.
  - Each side can have a minimum size; the divider cannot be dragged past
    it.
  - Fires a change event when the divider moves, so the position can be
    saved and restored.
  - Double-clicking the divider may reset it to its default position.


Window
------
A top-level panel that floats above the Viewport's content.

  - Has a title bar showing a title and minimize, maximize and close
    buttons, and a content area that holds a single child widget.
  - Moved by dragging the title bar; it is kept within the Viewport so the
    title bar can always be reached.
  - Resized by dragging its edges or corners, down to a minimum size.
  - close() removes the window from the Viewport. A close event is fired
    first, and a handler may cancel it (for example, to confirm unsaved
    changes).
  - Clicking anywhere in a window brings it to the front; isFront tells
    whether it is the front-most window.
  - The front-most window that is showing is the active window: it has
    the stronger title bar and shadow, and the others are drawn inactive.
    isActive tells whether a window is the active one.
  - minimize() hides the window; open() restores it. In the playground each
    minimized window gets a button on the StatusBar, and the Windows menu
    restores it too. minimized tells whether it is minimized.
  - maximize() makes the window fill the Viewport between the Navbar and
    the StatusBar, and keeps it fitted when the browser is resized; restore()
    puts it back where it was. toggleMaximize() switches between the two, and
    double-clicking the title bar calls it. A maximized window cannot be
    moved or resized; maximized tells whether it is maximized.
  - Minimizing, restoring, maximizing and un-maximizing fire a windowstate
    event that bubbles up to the Viewport.
  - Has a ButtonBar (window.buttonBar) along its bottom edge, 30px high,
    below the content area. Subclasses add their buttons to it.
  - The resizable option (true by default) can be set to false for a window
    of fixed size: it has no resize edges and no maximize button, and
    cannot be maximized (double-clicking the title bar does nothing).
    arrangeWindows() moves such a window without resizing it.


TextPanel
---------
A Panel that contains a single text area filling its entire area.

  - The text area is created by the panel and always sized to match it; no
    other children can be added.
  - Exposes the text through a text property (get and set), and fires a
    change event when the user edits it.
  - Can be made read-only, e.g. for program output.
  - focus() moves the keyboard focus into the text.
  - Ctrl+Enter (Cmd+Enter on a Mac) fires a submit event.


MonacoPanel
-----------
A TextPanel whose text is edited in a Monaco editor (the editor behind VS
Code), highlighted for a Monaco language id: new MonacoPanel({ text,
language }), e.g. language 'vb' for VB.NET.

  - Monaco is loaded from cdn.jsdelivr.net the first time a MonacoPanel is
    created, and shared by every later one. Until it arrives the panel works
    as a plain TextPanel; the text typed meanwhile carries over into the
    editor. If it cannot be loaded (e.g. offline), the panel stays a plain
    TextPanel.
  - The text and readOnly properties, focus(), append() and the change and
    submit events work the same with or without the editor.
  - ready is a promise that resolves once the editor is up (to the editor,
    or null if Monaco could not be loaded).


ListPanel
---------
A Panel that is filled by a single List element.

  - The List is created by the panel and always sized to match it; no other
    children can be added.
  - Items are added, removed or replaced through the panel, and the List
    scrolls when they do not fit.
  - Tracks the selected item and fires a select event when the user picks
    one (by click or keyboard).
  - Items are {label, value} objects: items (get and set), addItem(item),
    removeItem(index) and replaceItem(index, item). The selection follows
    the item's value, so replacing all the items keeps the same row
    selected. selectedIndex, selectedItem and select(index) give access to
    it; Up, Down, Home and End move it.
  - An optional emptyText is shown when there are no items.


TabPanel
--------
A Panel showing one of several pages at a time, chosen by a row of tab
labels.

  - new TabPanel({ tabPosition }): the labels run along the 'top' (the
    default) or the 'bottom' edge, in a 24px strip; the page showing fills
    the rest.
  - addTab(label, widget) adds a page and returns the widget. Pages are
    added only this way; add() is an error. The first page added is
    selected.
  - Clicking a label shows its page and hides the others. select(index or
    label) does the same from code, and fires a select event with detail
    {index, label, widget}.
  - labels, selectedIndex, selectedLabel and selectedWidget describe the
    tabs and the page showing. remove(widget) removes a page and its tab.


OutputPanel
-----------
The output side of a ConsoleWindow: a TabPanel with its labels along the
bottom and three pages.

  - Text: a read-only TextPanel (outputPanel.textPanel) that programs print
    to. It is selected at first.
  - Board: a BoardPanel (outputPanel.boardPanel).
  - Canvas: a CanvasPanel (outputPanel.canvasPanel).
  - selectedTab is the label of the page showing; selectTab(label) shows
    another.
  - clear() empties all three pages. No other children can be added.


BoardPanel and CanvasPanel
--------------------------
The Board and Canvas pages of an OutputPanel. For now both are placeholders
that show their name; clear() does nothing.


Navbar (singleton)
------------------
The navigation strip docked along the top of the Viewport. Navbar is a
subclass of HPanel, so its contents are laid out left to right using the
same fixed-size and flex rules.

  - Exactly one instance exists; obtain it with Navbar.instance. Calling
    the constructor a second time is an error.
  - Added to the Viewport (viewport.navbar = Navbar.instance), which docks
    it at the top of the page.
  - Is 35px high and spans the full width of the Viewport. Windows cannot
    be dragged above it.
  - Its children are a title or logo on the left and the navigation items,
    typically Menus; a flex spacer can push items to the right-hand end.
  - Each item has a label and an action; the active item is highlighted.
  - Items that do not fit may collapse into an overflow menu on narrow
    screens.


StatusBar (singleton)
---------------------
The status strip docked along the bottom of the Viewport. StatusBar is a
subclass of HPanel.

  - Exactly one instance exists; obtain it with StatusBar.instance. Calling
    the constructor a second time is an error.
  - Added to the Viewport (viewport.statusBar = StatusBar.instance), which
    docks it at the bottom of the page.
  - Is 24px high and spans the full width of the Viewport. Windows cannot
    be dragged below it.
  - A message Label on the left (message, or show(text, tone) where tone
    'error' shows it in red) and an info Label on the right (info).
  - setTasks([{label, title, action}]) shows a row of buttons between the
    message and the info; the playground uses it for minimized windows.
  - In the playground the consoles report on the message (running, finished,
    stopped, load errors) and the info shows a live summary of the
    scheduler's processes.


Menu
----
A pulldown menu: a labelled button that opens a list of items when clicked.
Menu is a Widget, not a Panel; its items are not widgets.

  - addItem(label, action, { checked, enabled }) adds an item. Choosing the
    item closes the menu and runs action(). If enabled is given, it is
    called each time the menu opens and the item is greyed out and cannot be
    chosen while it returns false.
  - addSubmenu(label, items) adds an item with an arrow that opens a
    submenu beside it (to the right, or to the left if there is no room)
    when pointed at or clicked. items is a function called each time the
    submenu opens, returning items in the itemsProvider shape. Only one
    submenu is open at a time, and choosing an item in it closes the menu.
  - addSeparator() adds a dividing line; an itemsProvider can return
    {separator: true} for the same.
  - If checked is given, it is a function called each time the menu opens;
    a check mark is shown next to the item while it returns true.
  - Only one menu is open at a time. Clicking outside the menu or pressing
    Escape closes it.
  - The list is drawn above all Windows, and kept inside the browser window:
    it opens below the menu's button, or above it when there is no room
    below (as for a menu in a Window's ButtonBar).
  - In a ButtonBar a Menu is drawn like the Buttons beside it, with a small
    down arrow after its label.
  - Setting itemsProvider to a function makes the menu dynamic: the function
    is called each time the menu opens and returns the items to show, in the
    same {label, action, checked, enabled} shape. "(none)" is shown for an
    empty list.


Startup
-------
Crumb.ui.start() picks the UI for the device (isMobileDevice() in
src/ui/device.js): on a phone it calls startMobile(), otherwise
startDesktop(). A ?ui=mobile or ?ui=desktop page parameter overrides the
detection. A phone is a browser that reports itself as mobile, a mobile
user agent, or a touch screen whose short side is under 600px; tablets get
the full UI.

The mobile UI (src/ui/mobile/app.js) is, for now, a single landing page
with the name, a short description, a link to the full version
(?ui=desktop) and the build time. It uses plain DOM and the theme
variables, not the desktop widgets.

When the full UI starts, the Navbar is docked at the top of the Viewport
with, from left to right, a File menu, a Database menu, Basic, Python and
Process buttons, a Settings menu, and a Windows menu, which is always the
last menu. At the right end is the time the page was built, e.g.
"Built 2026-09-23 13:47:05 UTC". The
StatusBar is docked at the bottom, and the TranscriptWindow is open.

  - The File menu has New Basic and New Python; then Open..., Save and
    Save As...; then Delete, with a separator between the groups.
    - New Basic and New Python open an empty console in that language.
    - Open... asks for a source file and opens it in a new console: .crumb
      and .bas files in a BasicConsoleWindow, .py files in a
      PythonConsoleWindow. The console's title shows the file name.
    - Save writes the front-most console's source back to its file; for a
      console with no file yet it does what Save As... does.
    - Save As... asks where to save the front-most console's source.
    - Save and Save As... are greyed out unless the front-most showing
      window is a console.
    - Delete asks for confirmation, then deletes the front-most console's
      file. The source stays in the console, which no longer has a file.
      It is greyed out unless that file was opened or saved through the
      File System Access API (Chrome, Edge), since other browsers give a
      page no way to delete files.
    - Where the browser has the File System Access API (Chrome, Edge), Save
      writes the file in place. Elsewhere Open uses a file chooser and Save
      downloads the file.
  - The Database menu has Basic and Python items, which open the
    BasicDatabaseWindow and PythonDatabaseWindow (or bring them to the
    front).
  - The Basic button opens a new BasicConsoleWindow.
  - The Python button opens a new PythonConsoleWindow.
  - The Process button opens the SchedulerWindow (or brings it to the
    front).
  - The Settings menu has three items that open submenus, each with a check
    mark on the choice in use. Choosing one takes effect at once and is
    remembered for the next visit.
    - Theme: Classic, Smalltalk or Apple.
    - Code Font: JetBrains Mono (the default) or IBM Plex Mono, used for
      source, output and lists, and in the Monaco editor. The font is
      fetched from Google Fonts when first chosen; until it arrives, or if
      the page is offline, the theme's own monospace font is used.
    - Database: Remote (https://fastblip-e2ba34b072c4.herokuapp.com, the
      default) or Local (http://localhost:3000). Open Database windows
      reload from the new server.
  - The Windows menu lists every open window by title, front-most first,
    with a check mark on the front-most one. Choosing a window shows it (if
    hidden) and brings it to the front.
  - The TranscriptWindow is always listed, so choosing it reopens it after
    it has been closed.


Button
------
A clickable, labelled Widget.

  - new Button(label, action); clicking it runs action().
  - label and enabled properties.
  - Used on the Navbar and in ButtonBars.


ButtonBar
---------
A row of Buttons along the bottom of a Window. ButtonBar is a subclass of
HPanel.

  - Is 30px high and spans the full width of the Window.
  - addButton(label, action) creates a Button, adds it and returns it.
  - Buttons are left-aligned, in the order they were added.


HSplitWindow
------------
A Window whose content is an HSplitPanel.

  - left and right properties get or set the two sides of the split.
  - Accepts the usual Window options plus left, right and position (the
    fraction of the width given to the left side).


ConsoleWindow
-------------
An HSplitWindow for editing and running code: the shared base of the
language consoles below. Any number of consoles can be open at once.

  - The left side is an editable TextPanel holding the source; the right
    side is an OutputPanel (console.outputPanel) with Text, Board and
    Canvas tabs. console.output is its Text page, which programs print to.
  - Its ButtonBar has, from the left, Run (runs the source), Clear Output
    (empties every page of the OutputPanel) and Clear Input (empties the
    source) buttons. Ctrl+Enter in the source also runs it.
  - After Clear Input comes a Priority menu (console.priorityMenu) with items 1 to 5; the
    chosen one is checked and kept in console.priority (default 3). The
    console's programs run at that priority on the Scheduler (1 highest,
    5 lowest), and choosing one also changes the priority of the program
    running now (setPriority(level)).
  - console.compiled is compiled code that came with the source (a
    record's compiled_code, when opened from a DatabaseWindow). Run and
    Launch use it instead of compiling for as long as the source still
    matches it; see "Compiled code" below.
  - After Priority comes a Launch menu (console.launchMenu), placed like
    the other buttons, with Desktop and Mobile items. They call
    launch('desktop') and launch('mobile'), which open a new
    DesktopLaunchWindow or MobileLaunchWindow with a copy of the console's
    source.
  - A subclass sets its language by overriding the static titlePrefix
    (e.g. 'Basic Console') and defaultText (the starting source), and the
    run() and stop() methods. In ConsoleWindow itself both do nothing.
  - The static spawn(source, { name, output, onExit }) compiles source in
    the console's language and spawns it on the shared Scheduler, printing
    to output (a TextPanel); load errors are written to output instead. It
    returns { process, errorCount } and does not start the scheduler. run()
    and LaunchWindow's Go both use it. In ConsoleWindow it spawns nothing.
  - createInput(text) makes the source pane: a TextPanel unless a subclass
    overrides it (e.g. with a MonacoPanel).
  - Each subclass numbers its own windows: the first is titled with the
    prefix alone, then '<prefix> 2', ... Every new console, of any kind,
    opens slightly below and to the right of the previous one.
  - Closing a console calls stop().


BasicConsoleWindow
------------------
A ConsoleWindow that runs Crumb code, titled Basic Console, Basic Console 2, ...

  - The source pane is a MonacoPanel with VB.NET highlighting.
  - While its program runs, the console's output pane is dimmed a little
    (running is true); it returns to normal when the program ends.
  - Run compiles the source and starts it on the Scheduler shared by all
    consoles (src/ui/runtime.js), so programs run in the background, take
    turns, and a Sleep never freezes the page. Output appears as it is
    printed. Running again, or closing the console, stops its previous
    program.
  - Load and runtime errors are shown in the output, in the section 11
    diagnostic format.
  - Lines written by the Transcript built-in are appended to the
    TranscriptWindow rather than to the console's output.


PythonConsoleWindow
-------------------
A ConsoleWindow for Python code, titled Python Console, Python Console 2, ...

  - Starts with print("Hello, world") as its source.
 

LaunchWindow (abstract)
-----------------------
A Window that runs a console's program as an app. Launch windows are
opened from a console's Launch menu; any number can be open at once.

  - new DesktopLaunchWindow({ source, console }) or
    new MobileLaunchWindow({ source, console }): source is the program and
    console the ConsoleWindow it came from (kept as window.source and
    window.console). The source is a copy taken at launch: editing the
    console afterwards does not change it. The console's class
    (window.language) runs it, so Go still works after the console closes.
  - Titled with the name of the script loaded in the console that launched
    it (console.scriptName): the console's file name, e.g. fizzbuzz.crumb;
    for a console opened from a DatabaseWindow, the record's name; otherwise
    the console's title (e.g. Basic Console 2).
  - Each new launch window opens slightly below and to the right of the
    previous one.
  - The content (window.screen) is the app's screen, an AppScreen: a
    TextPanel (window.textPanel) that fills all of it, which the program
    prints to, with the program's widgets (New Button, ...) over it. The
    same in DesktopLaunchWindow and MobileLaunchWindow.
  - Its ButtonBar has Go and Reset buttons (window.goButton and
    window.resetButton), which call go() and reset().
  - The program starts by itself the first time the window is opened, once
    it is in the Viewport and laid out (a MobileLaunchWindow is fitted to
    its phone screen first), as if Go were pressed. Restoring the window
    after minimizing or hiding it does not run it again. Pass
    autoStart: false to the constructor to wait for Go instead.
  - go(), stop() and reset() are done by a ProgramRunner (window.runner),
    shared with the ?run= page.
  - go() stops any previous run, clears the text panel and removes the
    program's widgets, and runs the source
    on the Scheduler shared with the consoles, in the launching console's
    language (ConsoleWindow.spawn). Output, and load and runtime errors,
    appear in the text panel; the StatusBar reports when it starts and ends.
  - reset() stops the program, clears the text panel and removes the
    program's widgets.
  - Closing a launch window stops its program.

DesktopLaunchWindow
  - An ordinary window, 640 x 440 to start, that can be moved, resized,
    minimized and maximized.

MobileLaunchWindow
  - Preset to the size of a phone: the content area is exactly
    MobileLaunchWindow.screenSize, 360 x 640 CSS pixels, whatever the
    theme's title bar and borders (it is re-fitted when the theme changes).
  - It cannot be resized or maximized (resizable is false), but can be
    moved and minimized.
  - When opened it moves up, if need be, so it does not reach below the
    StatusBar.
  - Its text output is 2px larger than the theme's font size, and its
    colour is the theme's text colour mixed 25% towards black.


TranscriptWindow (singleton)
----------------------------
A Window showing the transcript: a log shared by every console.

  - There is only one; TranscriptWindow.instance creates it on first use,
    and constructing a second one throws.
  - Its content is a TextPanel (transcriptWindow.textPanel). Each call to
    the Transcript built-in from a BasicConsoleWindow appends one line to it and
    scrolls it into view.
  - Its ButtonBar has a Clear button, which empties the transcript
    (transcriptWindow.clear()).
  - Open at startup and always listed in the Windows menu (see Startup).
  - Closing it only hides it: the instance and its text are kept, and the
    Windows menu reopens it. dispose() discards the instance, and the next
    use creates a new one.


SchedulerWindow (singleton)
---------------------------
A Window listing the programs on the UI's shared Scheduler, so they can be
suspended, resumed or killed.

  - Its title is "Process", matching the Navbar button that opens it.
  - There is only one; SchedulerWindow.instance creates it on first use,
    and constructing a second one throws.
  - Its content is a ListPanel with one row per unfinished process: pid,
    name (the title of the console that started it), priority (P1 to P5),
    state (ready,
    running, sleeping, scheduled or suspended) and instructions executed.
    The list is refreshed every 250ms while the window is open, keeping
    the selection.
  - Its ButtonBar has Suspend and Kill buttons, which act on the selected
    process and are disabled when nothing is selected. When the selected
    process is suspended, Suspend reads Resume.
  - Then a Priority menu (items 1 to 5, the selected process's priority
    checked) that changes the selected process's priority.
  - A suspended process gets no turns; a sleeping one keeps the rest of its
    sleep for when it is resumed.


DatabaseWindow
--------------
An HSplitWindow that browses one table of source records on the database
server (rails/server): records are listed on the left ("id  name"), and the
selected one is edited in a RecordPanel on the right. Abstract: a subclass
sets the static table ('basic' or 'python', see src/ui/db-client.js),
language (the Monaco language id) and consoleClass. There is one window per
subclass, obtained with BasicDatabaseWindow.instance and
PythonDatabaseWindow.instance; closing it keeps its state.

  - Its ButtonBar has New, Save, Delete, Refresh, Compile and Open in
    Console buttons, a Priority menu (items 1 to 5; the chosen one is
    checked), and a status line at the right end.
  - Priority is the record's priority field (1 to 5, default 3). Choosing
    one marks the record changed; Save stores it.
  - Compile compiles the content in the editor with the consoleClass's
    static compileSource(). On success the chunk is stored as JSON (see
    src/vm/chunk-json.js), with a hash of the source it was compiled from,
    in the record's compiled_code field and the record is saved. On failure nothing is stored or saved; the error count and first
    error show in the status line, with the full text in its tooltip.
  - Selecting a row loads that record. New starts an empty record, which
    Save creates on the server; Save on an existing record updates it.
    Enter in the name, Ctrl+Enter in the content, or Ctrl+S also saves.
  - Delete asks for confirmation, then deletes the record.
  - Selecting another record, starting a new one or closing the window
    with unsaved changes asks before discarding them.
  - Open in Console opens a new console of the table's language holding
    the record's content, with the record's name as its scriptName.
  - The list is reloaded each time the window opens, and by Refresh.
  - The server is the one chosen in Settings > Database: Remote by
    default, or Local when the page is opened with ?db=local.
  - Errors from the server (for example "name can't be blank") or the
    network are shown in red in the status line.

BasicDatabaseWindow edits the basic_source table (VB highlighting, opens a
BasicConsoleWindow); PythonDatabaseWindow edits python_source (Python
highlighting, opens a PythonConsoleWindow).


RecordPanel
-----------
A Panel for editing one source record: a Name field and a caption along the
top, and the content in a MonacoPanel filling the rest.

  - name, content and caption properties; enabled makes both fields
    editable or read-only.
  - Fires change when the user edits either field, and submit on Enter in
    the name or Ctrl+Enter in the content.


Label
-----
A Widget showing one line of text (text property). tone = 'error' shows it
in red. Used for the status line of a DatabaseWindow's ButtonBar.


Spacer
------
An empty Widget with a flex weight (1 by default). Placed in an HPanel, it
takes up the free space, pushing the widgets after it to the right.


Theming
-------
Every colour, font, radius and shadow the widgets use is a CSS custom
property named --cr-*, defined in src/ui/theme.js. Widgets never hard-code
a colour; they write var(--cr-title-bg) and so on.

  - THEMES holds a set of values per theme:
      classic    the default: a Windows 2000-style desktop, with grey 3D
                 bevels, gradient title bars, Tahoma and a blue desktop
      smalltalk  after Smalltalk-80: black on white, striped title bars
                 with the title centred on a white label, hard drop
                 shadows and a dithered grey desktop
      apple      a present-day Mac desktop: a translucent, blurred menu
                 bar, a soft gradient wallpaper, large rounded windows with
                 deep shadows, centred titles, and red, yellow and green
                 circular window buttons on the left whose symbols show
                 on hover
      light      the original flat look
      dark       a dark version of it
    Values shared by every theme are defined once, and a theme overrides
    only those it changes. Besides colours there are shape variables:
    window padding, title weight and alignment, raised button and title-bar
    button bevels, the size, shape, colour and order of the title-bar
    buttons (a negative order puts them before the title), rounded and
    blurred menus and bars, the window corner radius (windows have slightly rounded
    corners and soft shadows; a maximized window is square) and how far a
    running console's output fades.
  - Settings > Theme offers Classic, Smalltalk and Apple (MENU_THEMES). Light and
    Dark remain available from code.
  - setTheme(name) switches theme by setting data-cr-theme on <html>, and
    remembers it in localStorage ('crumb.theme'), so the next visit starts
    with it. setTheme('auto') follows the operating system's light or dark
    setting. themeName() is the theme chosen, resolvedTheme() the one in
    effect.
  - A cr-themechange event on document announces each change. The Viewport
    lays everything out again on it (a theme can change fonts, padding and
    borders), and MonacoPanel switches the editor's own theme, since Monaco
    cannot read CSS variables.
  - The code font is separate from the theme (src/ui/fonts.js): it sets
    --cr-font-code, which falls back to the theme's --cr-font-mono, and a
    cr-fontchange event tells Monaco to switch font and re-measure.
  - A new theme is one more entry in THEMES. In the browser the API is
    Crumb.ui.setTheme(...).


ProgramRunner
-------------
Runs one program for the Go and Reset buttons, in LaunchWindows and on the
?run= page (src/ui/program-runner.js). Not a widget.

  - new ProgramRunner({ language, source, screen, name, compiled,
    priority }): language is the
    ConsoleWindow class whose static spawn() compiles the source
    (BasicConsoleWindow or PythonConsoleWindow), screen the AppScreen it
    runs on (it prints to screen.textPanel and puts its widgets on
    screen.host), and name (a string, or a function returning one) the name
    shown in the scheduler and the StatusBar. compiled is compiled code for
    the source (see "Compiled code") and priority the process's priority,
    1 to 5; each may also be a function, read at every Go. Instead of a
    screen, output can give a bare TextPanel; the program then cannot use
    widgets.
  - go() stops any previous run, clears the output and the widgets, and
    starts the source on the shared Scheduler. Output, and load and runtime
    errors, appear in the output; the StatusBar reports when it starts and
    ends.
  - stop() stops the program; reset() stops it and clears the output and
    the widgets.


The ?run= page
--------------
Opening the page with ?run=<program name> runs that program as a full-page
app instead of the playground (src/ui/run-app.js, startRuntime(name)). It
works on any device, phone included.

  - The browser window (tab) is titled with the program name.
  - The source is read from the database server in use (Settings >
    Database, or ?db=local): the record with that name in the Basic table,
    else in the Python table, matching the name exactly, else ignoring
    case. The table decides the language. The record's compiled_code, if
    it matches the content, is run without compiling, and the program runs
    at the record's priority.
  - The Viewport has no Navbar or windows: its content is an AppScreen that
    fills it (a TextPanel with the program's widgets over it), and a
    ButtonBar with Go and Reset buttons is docked along its bottom.
  - Go and Reset act as in a LaunchWindow (a ProgramRunner does both).
  - The program starts by itself as soon as it has loaded from the
    database, as if Go were pressed.
  - While the program loads, the text panel says so and the buttons are
    disabled. If there is no such program, or the server cannot be reached,
    the text panel says so and the buttons stay disabled.


Compiled code
-------------
A program runs from compiled code instead of being compiled each time,
wherever it runs in the browser: consoles (Run), launch windows (Go) and
the ?run= page. ConsoleWindow.spawn gets a chunk from loadProgram
(src/vm/program-loader.js), which tries, in order:

  1. The compiled code given with the program (a record's compiled_code,
     made by a DatabaseWindow's Compile button). It is used if it loads
     (right format, made for this instruction set) and records the hash
     of the same source; compiled code left over from before the content
     was edited, or saved without a hash, is ignored and the source
     compiled instead. A record with compiled code and no source runs from
     the compiled code alone.
  2. The page's compile cache: the last 64 programs compiled or loaded,
     by language and source, so running a program again (Run, Go, Reset
     and Go) does not compile it again.
  3. Compiling the source, which adds it to the cache.

Every load builds a fresh chunk (MiniPy's runtime library included), so
two runs never share state. The StatusBar says which was used:
"running (pid 4, compiled code)", "(pid 4, cached)", or just "(pid 4)"
when the source was compiled.


AppScreen
---------
The screen a program runs on, in a LaunchWindow and on the ?run= page
(src/ui/widgets/app-screen.js).

  - A TextPanel (screen.textPanel) fills it: the program's Print output.
  - Over it, a transparent layer (screen.widgetLayer, a FreeLayer) holds the
    widgets the program makes. Clicks outside them go through to the text.
    The program's Labels are opaque, so printed text does not show through.
  - screen.host, a ProgramWidgetHost, is what the VM calls to make and
    change the widgets (its `gui` option).
  - clearWidgets() removes them all (Go and Reset do this).


Program widgets
---------------
Programs build their screens from this toolkit (spec section 10.1). Every
general-purpose class is available, in Crumb as an object made with New and
changed through methods, and in MiniPy the same way with Python spellings:

  Dim label = New Label("Hello")        label = Label("Hello")
  label.setWidth(100)                   label.set_width(100)

  - The classes: Label, Button, Menu, Spacer, Panel, HPanel, VPanel,
    ButtonBar, HSplitPanel, VSplitPanel, TabPanel, Window, TextPanel,
    MonacoPanel and ListPanel. Left out on purpose: the singletons
    (Viewport, Navbar, StatusBar, TranscriptWindow, SchedulerWindow), the
    IDE's own windows (consoles, DatabaseWindow, LaunchWindows) and panels
    made for them (RecordPanel, OutputPanel), and the BoardPanel and
    CanvasPanel placeholders.
  - A program's Panel is a FreePanel: its children sit where the program
    puts them (the toolkit's Panel is abstract).
  - The classes and their methods are one table, WIDGET_CLASSES in
    src/vm/runtime/widgets.js, shared by both languages: each method's
    Crumb name (camelCase), MiniPy name (snake_case), argument kinds and
    result kind. The Crumb compiler checks method names and argument counts
    against it at load time.
  - ProgramWidgetHost (src/ui/program-widgets.js) implements the host
    interface: create(className, args) -> id, has(id), classOf(id) and
    call(id, method, args) -> result. Ids count from 1; each program object
    holds its id. Widgets the host makes itself (a Window's ButtonBar, the
    Buttons made by ButtonBar.addButton) get ids when the program first
    reaches them. A call the program got wrong (an index out of range, a
    Window put inside a panel, a widget put inside itself) throws a
    WidgetError, which the program sees as a runtime error.
  - Layout. A new widget goes on the FreeLayer at its class's default box
    (Label 100 x 24, Button 100 x 32, HPanel 320 x 32, other containers
    320 x 200, ...). On the layer and in a Panel a widget sits at the box
    the program gave it, or fills the area after fill(). In an HPanel,
    VPanel or ButtonBar, setWidth / setHeight set fixedWidth / fixedHeight,
    setFlex sets flex, and otherwise the widget's natural size is used
    (its text's width for Labels, Buttons and Menus; its class's default
    size for the rest). Program Windows float on the layer; they have no
    minimize button, since the screen has no StatusBar to restore them from.
  - Events: onClick, onSelect, onChange, onSubmit, onClose and Menu.addItem
    register handlers. The host calls the VM's callback with the event's
    value (a row or tab index, the new text, the divider position, the
    item's label); the VM queues it and runs the handler, with the widget
    and that value as its arguments, when the program is idle. A program
    with a handler keeps running after its top-level code, waiting for
    events (its process shows as 'waiting' in the Process window), until
    it is stopped. examples/widget-tour.crumb and widget-tour.py show most
    of the classes; examples/button-demo.crumb is a small one.
